# Trained TinyLlama massive F16 campaign

This campaign broadens NNIS evidence beyond the pinned SmolLM2-135M path by using the trained `TinyLlama/TinyLlama-1.1B-Chat-v1.0` checkpoint. It is deliberately exploratory: it does not authorize a runtime default change, a candidate promotion, or a claim of general Llama-family support.

## Pinned model

- Repository: `TinyLlama/TinyLlama-1.1B-Chat-v1.0`
- Revision: `d9128824c0c80111be21424e68086f52413fb413`
- `model.safetensors` SHA256: `6e6001da2106d4757498752a021df6c2bdc332c650aae4bae6b0c004dcf14933`
- Source dtype: BF16
- NNIS model-format-v1 persisted execution dtype: F32
- NNIS F16 benchmark resident dtype: F16
- Geometry: hidden 2048, intermediate 5632, 22 layers, 32 query heads, 4 KV heads, head dimension 64, context 2048.

The fixture generator verifies all of these fields before conversion and fails closed on any upstream drift. The untied upstream LM head is persisted explicitly rather than being synthesized from the token embedding.

## Massive suite

`tools/tinyllama_1p1b_chat_fixture.py` builds 18 deterministic trained-model oracle cases from three prompt families (`prose`, `code`, `math`):

- prompt lengths: 8, 32, 128, 512, and 1024 tokens;
- 32 greedy decode tokens for every prompt length;
- one additional 128-token decode at a 32-token prompt for each family;
- exact greedy IDs generated by pinned Transformers 4.43.3 on CPU with the exact checkpoint widened to F32.

The F16 benchmark treats equality with those greedy IDs as a semantic gate. This is not full-logit numerical equivalence because NNIS explicitly narrows the persisted F32 graph to resident F16.

## Candidate matrix

The reference is F16 numeric alignment + `[K,N]` projection layout + reference attention. Every candidate is compared independently against that reference:

- `transposed`: resident `[N,K]` projection candidate;
- `fused`: transposed layout plus grouped projection launches;
- `fused_mlp`: transposed layout plus grouped QKV and fused gate/up/SiLU;
- `staged`: reference projections plus staged-weight attention from KV row 16;
- `fused_mlp_staged`: combined fused-MLP projection plan plus staged-weight attention.

KA17 `parallel-score` is intentionally excluded. Its current NNIS validator is fail-closed to the exact SmolLM2-135M geometry and must not be bypassed for cross-model testing.

For staged attention, each block preflights the kernel's maximum supported KV rows. The block is rejected before timing if the complete suite would require resource fallback.

## Default physical campaign

One launcher invocation performs two complete campaigns under distinct `run_context_id` values. Each campaign performs four ABBA rounds for each of the five candidates. Every ABBA slot builds the selected model plan once and runs all 18 cases. Case order is forward on even rounds and reversed on odd rounds while remaining identical across the four slots of a round.

Defaults per case/slot are one warmup plus three measured requests. Therefore the default one-command campaign comprises:

- 2 independent complete campaigns;
- 5 candidate-vs-reference comparisons;
- 4 ABBA rounds per candidate;
- 160 model-plan constructions across both campaigns;
- 11,520 generation requests including warmups;
- 552,960 generated tokens;
- more than 3.3 million prompt tokens processed before generated-token accounting.

Model construction is reported but excluded from request latency. Raw generation GPU, generation wall, request wall, prefill GPU, session setup, generated IDs, environment fingerprint, Git identity, and CUDA memory snapshots are retained in JSON evidence.

## One-command execution

From a clean NNIS checkout at the exact commit to be tested:

```bash
python3 tools/run_tinyllama_massive_campaign.py \
  --work-dir /root/nnis-tinyllama-massive \
  --device 0
```

The launcher:

1. creates or reuses the exact pinned trained-model fixture;
2. builds `llama_f16_massive_abba` in release mode with `--locked`;
3. refuses a dirty tracked worktree;
4. runs every repeat even if a prior repeat records a failure;
5. writes raw campaign JSON, `consensus.json`, and `SUMMARY.md`;
6. compares normalized environment fingerprints across independent repeats;
7. exits non-zero if the independent consensus is invalid.

The fixture step requires the packages pinned in `tools/requirements-tinyllama-1p1b.txt`. On Jetson systems, use the PyTorch build appropriate for the installed JetPack/CUDA stack rather than replacing a working NVIDIA PyTorch installation solely to satisfy a generic wheel pin.

## Claim boundary

A successful consensus means only that the exact trained TinyLlama checkpoint, fixture suite, F16 numeric contract, selected candidate plans, Git head, and compatible physical environment completed the declared comparisons while preserving the trusted greedy trajectories. Cross-model evidence can expose portability or regressions, but it does not promote candidates qualified previously on SmolLM2 and does not establish general model-family support.
